## 2. Minimal shared layer

One low-level module, e.g. `src/lib/suppliers/purchase-state.ts`, imported by wrappers at their existing paths. Two static, closed descriptors (`wr_order_links/wr_order_id/wr_variant_id/wr_link_id` and SK equivalents; purchase owner prefix `cron` vs `sk-cron`; 120-second lease). Leave max defaults and each row's actual max with the caller. Jaspay uses the WR descriptor for normal purchase claim/fence, not its replay lease. Bind all values, never interpolate untrusted identifiers/status/fields. Use typed unions for allowed fields on a CAS; no arbitrary SQL fragments from callsites, adapter factory, registry, generic runner, transport callbacks, or DTO rewrites. Preserve SQL semantics including `COALESCE` vs strict NULL and `datetime()`; existing entrypoints and result adapters remain in supplier modules.

## 4. H4 admission and crash boundary (behavioral, owner approval before coding)

**C2 local measurement (supersedes the proposed counts below):** 26 after due SELECT: 8 through final CAS, 4 link settlement, 14 strict aggregate/notice/ACK. Replay is 4 + 14 work plus two scans and two cursor writes (22 total, excluding two reserved tail slots). See ARCHITECTURE for the drain/rollback rule; not deployed.

**Proposed first conservative floor:** at `W:398`, before counting the candidate or touching claim/HTTP, `const final = Number(link.attempt_count) + 1 >= Number(link.max_attempts || WR_MAX_ATTEMPTS); if (!db.canSpend(final ? 24 : 6)) break;`. Keep ordered selection and tail; use the same capped `DatabaseAccess` throughout. **24 = 8** worst final stock prefix through failure CAS (7 fresh, +1 inline takeover) **+ 1** binding/order evidence read **+ 1** guarded item write **+ 13** terminal aggregate with strongest notice branch **+ 1** completion marker ACK. Code to that statement envelope; if a design needs another statement, change the number and boundary test, never silently borrow tail. The binding read includes both directions/order state. True unbound legacy fallback replaces item+aggregate writes with one guarded orders write + existing notice. No new paid readers, GETs or POSTs. Baseline 6 remains for non-final WR; SK retains 6/14, separate 11/17, and existing throw. This reserves the H4 branch, **not** full synchronous Jaspay credential delivery; its receipt still needs to persist first, and existing known-invoice backstop remains. Keep optional stock revision bump after loop guarded. Require snapshot max/attempt still authoritative at claim/takeover; current writers don't change `max_attempts`, but if supporting concurrent limit edits, add matching `max_attempts` CAS in this H4 commit (or conservatively admit under 24 before any POST). Never discover insufficient budget only after a final POST.

**Implementation shape.** Two WR handlers converge only at their final definitive rejection (not malformed local Jaspay config, ambiguous error, balance, or known-invoice handler). Winning link-CAS persists the actual reason and durable settlement-needed proof in the **same** write; a narrow additive WR marker with default clear is preferable to guessing from `attempt_count`, changing supplier error text, or overloading `next_attempt_at`. New recovery reads that marker only, not historical failures. Do not let Admin Retry rearm while settlement is pending (repeat in CAS, and maintain old behavior after clear). Item transition must recheck same order, link binding/conflict, paid/enabled and not delivered/sending/manual (`manual_handover:*` **or** `delivered_message_id='manual'`); item already failed by this work is resumable. When there is a bound but protected/conflicted item or lost CAS, do **not** infer legacy unbound. If no forward or reverse binding and no conflict, old legacy fallback with explicit reason/log; recheck no binding in its UPDATE. Suppress direct buyer notify on bound path; use existing `refreshOrderAggregate` and failure-notice ledger. Keep existing admin copy and make admin notice only on the initial winning fail transition (as today).

**Don't confuse budget with crash safety.** A bare `canSpend` will not survive Worker termination or a failed D1 write. Use the durable marker for a bounded no-POST replay from existing WR recovery ticks **outside** due-purchase count/auto dispatch gates (`lite/route.ts:510–539`, operations WR `:962–996`), at most a small ordered batch; reserve **16 per replay row** (24 minus prefix 8, scan separate; don't add hidden per-row queries). Marker only ACKs after authoritative terminal/protected decision or aggregate success, not after a swallowed SQL error. H4 needs a narrowly opted-in strict aggregate path using the **same aggregate algorithm**, not a second competing algorithm: propagate DB errors to retry marker, recheck paid/failure/active-sibling predicates at failed UPDATE, and check rows changed before notice. If crash after aggregate commit and before notice, replay may resume the same notice key only with current valid failed order + this durable H4 evidence; never notify an active or protected cart. Idempotent ledger, not exactly-once external delivery across a provider timeout. Keep notice best-effort like baseline; any stronger durable delivery guarantee is a separate contract. Recheck payment/order and sibling races in SQL rather than widening generic aggregate semantics. If marker/schema + replay or bounded transactional alternative is not approved, keep H4 deferred; a reserved budget alone is not an interruption/retry guarantee.

For mixed carts, keep aggregate work discoverable while the sibling is active; exclude already-item-settled rows from the replay candidate scan until they can advance, so they don't occupy its limited slots every tick. This provides a final aggregate backstop even if a sibling's completion path doesn't call the WR helper. Distinguish a legitimate active sibling from a binding conflict or SQL failure. A one-bit link marker that blocks Retry until all siblings settle can delay legitimate intervention; get that policy approved or separate *link settlement pending* (Retry fence) from *aggregate refresh pending* (order-level, no Retry fence), and remeasure the latter if it adds writes. Test that long-lived markers don't block other orders and that temporarily unpaid or protected cases can't bypass CAS or fallback.

**Cost/risk tradeoff.** Any WR last attempt (even a success) now waits a tick if only 6–23 slots remain; FIFO means it can hold the tail briefly. Preserve FIFO, report budget deferral explicitly in diagnostics without inventing success/failure counts, give existing WR tick sufficient phase priority, and test healthy next-tick progress; do not raise global budget or skip over older rows unchecked. `canSpend` works as a floor with sequential/awaited metered use (operations awaits phases `:1483–1497`, lite uses one job); immediate paid dispatch creates unbudgeted access per supplier (`payments/paid-fulfillment.ts:82–116`). If a new caller shares one meter concurrently, require real sub-budget reservation or serialize before supporting it. An owner-approved smaller H4 change can choose durable deferred settlement instead of a 24-statement inline requirement, but do not ship it as a mechanical refactor or claim synchronous single-item parity without proving it.
