## Pembelian, pemulihan, dan pengiriman — 18 November 2026

- Hanya baris order apps web/Telegram lunas/paid dengan snapshot `storebat_eligibility` yang dibuat server; bukan order lama tanpa snapshot, payment test, atau order dengan pembelian supplier dimatikan. Satu link per order/baris dan key stabil `<order_code>-<item_index>`; order biasa memakai key itu juga sebagai `customer_reference`. Tidak ada perpindahan supplier atau pembelian ulang karena gagal kirim.
- Preflight mengecek pemilik fulfillment, mapping dan status aktif, quote live (stok/jenis, harga satuan × jumlah dan total tidak boleh di atas snapshot) serta saldo (fallback `/me` untuk quote Muse tanpa saldo). Saldo kurang/HTTP 402 → `blocked_balance`; harga naik → `price_increased`. `activation` atau `AWAITING_ACTIVATION_INFO`/`AWAITING_ACTIVATION` pada order biasa → `needs_admin` (`activation_required`), bukan pembelian aktivasi otomatis. Supplier tidak menerima batas harga pada POST; preflight bukan jaminan harga atomik.
- Lease + compare-and-set memagari identitas, order lunas, ownership dan `request_sent_at` sebelum POST; maksimum tiga POST. Receipt mentah dan kode undangan Buff disimpan terenkripsi pada link. Bila ID supplier diketahui, poll GET ID yang sama; bila kirim ambigu tanpa ID, `GET /orders/lookup` pakai key identik. Lookup `completed` hanya mengadopsi ID untuk GET, bukan dasar delivery. Hanya `failed_no_charge` yang cocok tanpa order mengizinkan replay body/key sama; 404, `in_progress`, dan `uncertain` tidak. Retry admin hanya kasus aman pra-kirim (`attempt_count=0`, tidak ada sent marker/ID, alasan yang diizinkan).
- Barang biasa `PAID_PENDING_DELIVERY` → `processing`; `COMPLETED` dengan cukup `items[].account_data` untuk `stock`/`supplier_api` → `completed`, kirim akun/link melalui jalur kredensial existing. `CANCELLED`, receipt kurang/tidak cocok, atau state tidak dikenal → `needs_admin`. Muse menerima invite code alfanumerik 6 karakter (`muse_invite_code`), 1–30 unit miliar token. `fulfillment_status=pending` → poll; `succeeded` → selesai dengan notifikasi tanpa kredensial; `failed_refunded`/`review_required` → admin (refund supplier bukan otomatis refund pembeli). Fallback kompatibilitas membaca `state`/`status` saat `fulfillment_status` absen atau bukan string tak kosong.
